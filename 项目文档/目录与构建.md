# 目录与构建

文档集中在项目文档；必要源文件、配置及文本测试输入保留原路径。GitHub 的固定平台入口保持标准位置，文档区也保存完整副本。

从仓库根目录运行 `python3 构建.py --stage --ci --build-root /path/to/workspace/Build`，得到项目外的 `Build/NginxConfigGuard/源码`，其中恢复原文档输入供既有相对路径检查使用。`--build` 每次在外部 `Build/NginxConfigGuard/新构建` 创建独立源码、日志及产物，缓存集中在外部 Build。暂存清单只取 Git 已跟踪普通文件，检查每个来源路径分量并拒绝符号链接；恢复输入也必须属于跟踪清单且字节哈希一致。全部输入验证后才写暂存目录，不复制 `.git` 与未跟踪文件。

外部 Build 的实际路径不能落在源码仓库内；项目名只能为单层目录。项目、暂存与缓存路径逐段检查既有目录，拒绝链接或其他文件类型。调用者应独占源码和输出目录；本构建包装器不承诺抵抗另一进程并发替换路径。系统固有路径别名可在确定 Build 实际位置时解析，但解析后的输出位置仍须位于源码仓库之外。

无 Git 索引的解包源码应先放在中央 Build 中，再用 `python -m build --outdir /path/to/workspace/Build/发行` 进行原生构建。Python 构建需要解释器中已有 build 模块；CMake、npm、Cargo、Go 按项目 kind 选择。未适配的项目返回 OPEN_MANUAL_ADAPTER，仅完成暂存，不启动原有安装或启动脚本。

源码树不跟踪 Build 目录占位。旧验证报告对应原提交；v0.1.5 的构建、测试和发行应引用该版单独的 GitHub 回执。
